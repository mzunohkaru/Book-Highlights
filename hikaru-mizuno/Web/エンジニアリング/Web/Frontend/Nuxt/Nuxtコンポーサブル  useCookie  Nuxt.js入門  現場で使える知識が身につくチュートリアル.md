#### Highlights & Notes

> クッキーの値を簡単に読み書きできる

> useCookie

> クッキーの基本概念

> セッション管理: ユーザーのログイン状態やショッピングカートの中身を記憶する。パーソナライゼーション: ユーザーごとの表示言語やテーマ設定などを保存する。トラッキング: アクセス解析や広告配信に利用される場合もある。

> Web ブラウザに保存される小さなデータ片

> const counter = useCookie('counter')

> 有効期限の設定 (maxAge / expires)

> セキュリティ関連の設定 (httpOnly, secure, sameSite)

> maxAge: クッキーが何秒間有効であるかを整数で指定します。たとえば、3600 を指定すれば 1 時間有効という意味になります。小数点以下は切り捨てられます。expires: JavaScript の Date オブジェクトを使って、クッキーの明確な有効期限を指定します。両方のオプションを設定した場合、通常は maxAge が優先されるため、整合性を保つためには同じ日時を設定するのが望ましいです。

> httpOnly: true に設定すると、クッキーはクライアント側の JavaScript からアクセスできなくなり、サーバー側専用のクッキーとなります。これにより、クロスサイトスクリプティング（XSS）攻撃からクッキーの内容を守ることができますが、クライアント側でクッキーを操作する必要がある場合は注意が必要です。secure: true に設定すると、HTTPS 経由の通信時のみクッキーが送信されるようになります。これにより、通信の安全性が高まりますが、ローカル開発環境などで HTTP を利用している場合には問題となる可能性があります。sameSite: このオプションは、クッキーのクロスサイト送信を制御します。たとえば、'strict' を設定すれば同一サイト内のみでクッキーが送信され、'lax' や 'none' を利用することで、柔軟なクロスサイトポリシーを実現することができます。

> 適用範囲の設定 (domain, path)

> domain: クッキーが適用されるドメインを指定します。通常、指定しない場合は現在のドメインが利用されます。path: クッキーが有効となる URL のパスを指定することができ、これにより特定のパスに対してのみクッキーを送信することが可能です。

> encode / decode: クッキーの値は文字列で保存されるため、JavaScript のオブジェクトや配列を扱う場合はシリアライズやデシリアライズが必要です。デフォルトでは、JSON.stringify と encodeURIComponent を組み合わせたエンコード関数、decodeURIComponent と destr を組み合わせたデコード関数が使用されます。default: クッキーが存在しない場合に、初期値として返す値を指定する関数または Ref を設定します。readonly: このオプションを true に設定すると、クッキーは読み取り専用となり、後からの更新ができなくなります。watch: クッキーの変更を自動で監視するかどうかを制御します。デフォルトでは、ネストしたプロパティも監視する設定になっていますが、'shallow' や false に設定することで、監視範囲を調整することができます。

> その他のオプション

> 配列データを扱う場合、変更を直接反映させることはできないため、新しい配列として再代入する必要があります

> useCookie の注意点

> useCookie は、必ず Nuxt コンテキスト内（プラグイン、ミドルウェア、Vue の setup 関数など）で呼び出す必要があります
