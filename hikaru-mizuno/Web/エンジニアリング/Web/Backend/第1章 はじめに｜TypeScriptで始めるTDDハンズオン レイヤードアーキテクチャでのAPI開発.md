#### Highlights & Notes

> TDDとは

> Red: まずテストを書く（このテストは必ず失敗する）Green: テストを通すための最小限の実装を行うRefactor: コードを改善する（テストが通ることを確認しながら）

> 一つのテストで一つの機能を検証

> TDDのポイント

> 境界値のテストを重視

> テストの粒度を適切に保つ

> 空文字、最大長、特殊文字などの境界値をテストエラーケースの適切な処理を確認TypeScriptの型システムと組み合わせた堅牢な実装

> テストの意図を明確に記述

> テストケース名が機能や期待する動作を明確に説明

> Arrange-Act-Assert パターンに従った構造的なテスト記述

> コメントを使用して、テストの各段階を明確に区分
