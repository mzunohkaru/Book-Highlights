# B2Bの基礎知識

B2Bとは、カスタマーとユーザーの==PtoP==

## Actor

| エンドユーザー<br>（いわゆるユーザー） | 購買意思決定者<br>（カスタマー）        | 口添え人<br>（インフルエンサー）               |
| --------------------- | ------------------------- | -------------------------------- |
| プロダクトを直接触る人           | プロダクトにお金を出す、もしくは出すことを決める人 | プロダクトを買う際にエンドユーザーと意思決定者の間に入ってくる人 |

**それぞれの立場の人が理解できる情報の提供の仕方、宣伝の仕方をする**


## 購買意思決定者へのアプローチ

- 導入決定には、費用対効果（ROI）をクリアにする
    - ベネフィットを費用対効果で表すと
        - 収益増大
        - 生産性増大
        - コスト削減
        - 利益率の拡大
        - 安全性向上
        - etc
- 各種法規制対応する
    - ==しかるべきところにコミュニケーションが行き届いている==
	    - ISO
- プロダクトを提供する会社と、「どのような関係性を築いているのか？」「築いていけるのか？」
- B2Bプロダクトに顧客は、「買う」より「投資」している

==「お客様は神様」ではなく共通のゴールを持つ「ビジネスパートナー」==  
オンボーディングだけではなく、<u>オフボーディング</u>も必要


## Whole Product

![](whole-product.png)

- Generic Product
	- 置き換えプロダクト
		- 例）エクセルとスプシ
- Expected Product
	- 置き換え以上に魅力的な価値があるプロダクト
		- 例）スプシ + カレンダー
- Whole Product
	- 機能が素晴らしいだけでなく、外側の要件も満たされている
		- 例）カスタマーサポートなど

**ドメイン・業界のWhole Productのレベルを知る**


## 中の人の視点
- 顧客企業の「中の人」達は、
	- 会社の中で何を目的に活動しているのか？
	- どのようにパフォーマンスが評価されているのか？  
	- 業務プロセスやそのためのツールとしてどんなものを使っているか？
	- アウトプットをどのように報告したりシェアしているのか？
	- 仕事の中でどんな問題に直面しているのか？
	- どのような仕事がうまくいったことを証明しているのか？  
	- ボトルネックだと感じていることは？

## 絶対に避けるべきこと  
提供するプロダクトの中に以下の点が一つでも含まれると失敗する 
- 顧客企業側であまりに大きな変更を求められること  
- 使い方が難しい  
- プロダクトが約束できる価値に至らない  
- 業界標準的なプロダクトから応用しにくく、単なる置き換えではない  
- 顧客企業にとって価値が明確ではない  
- 使い慣れている既存プレイヤーとの真正面からの比較が避けられない

## 成功のために最低限すべきこと  

- ターゲット業界のビジネスがどのように成立しているのか？
- なぜトップ企業はトップたりえるのか？
- 現在抱えている業界の問題、変革の兆し、今どんな取り組みは行われようとしているか？  
- 業界の「中の人」の感覚を持つ  
- 業界で求められる`Whole Product`の概念を理解する  
- ROIを計測できる方法を見つけ出す  
	- 購買意思決定者にアプローチするため  
- 会社としてのリスク、プロダクトのリスクを最小化する（==リスクがない証明や、リスクが最小化するストーリーを提示する==）
	- 企業は年単位で契約及び予算を組むことを理解しておく

## 業界を理解する

B2Bにおける「マーケット」とは
（以下2つの条件を満たす顧客の集合）
1.　同種の問題やペイン、もしくは新たな機会を共有している  
2.　こうした人々をつなぐチャネルの存在や、購買意思決定の基準が比較的に似ている

### マクロ視点
以下の3つのマクロ視点で市場を見る。
また、成長率にも着目する。
#### TAM
全体（国、地域、業界単位）としてプロダクトに対してどのくらい需要があるのか？
市場全体の魅力を把握できる。

業界に存在するプレイヤーの売り上げを積算することで概算を掴める

#### SAM
自社のサービス提供可能な地理的範囲の中でどのくらい需要があるのか？
どの程度成長するのかを把握できる。
#### SOM
SAMのうち、現実的に獲得できそうな収益規模 or マーケットシェア
どの程度成長するのかとその伸び代を獲得できるかを把握できる。

SAMから実質の規模を推測するための要因
- プロダクトやサービスをオペレーションする際の限界値
- 実際に使ってくれる、買ってくれるユーザー規模
- ターゲットにリーチするためのマーケティング
- 競合に対してどこまで魅力的か？

## プロダクトライフサイクル

![](プロダクトライフサイクル.png)

#### 導入期（0 -> 1）
==PMFを見つける==

| Fit Type            | 意味                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Customer Fit        | Good fit customer：すぐに価値を感じてもらえて、長期的に使ってもらえる顧客<br>Stretch customer：価値を感じてもらえるが、長期的に使ってもらうにはいろいろ手を加える必要がある顧客<br>Bad customer：価値を感じてもらえない顧客 |
| Technical Fit       | 顧客に技術的に馴染んでもらえる知識や経験があるか？                                                                                                                |
| Functional Fit      | 顧客の課題を解決できるだけの機能は備えているのか？                                                                                                                |
| Experience Fit      | プロダクトのUXという意味だけでなく、対顧客企業という面で良い関係性が維持・構築できそうか？                                                                                           |
| Support Fit         | 顧客に何かがあった時、サポートできる体制があるのか？                                                                                                               |
| Internal Buy-in Fit | 顧客の各種ステークホルダーと意思疎通でき、足並み揃っているか？                                                                                                          |
![](Best%20Fit.png)
**現状のプロダクトにとって、Best Fitの顧客像を理解しておく**

#### 成長期（1 -> 10）
戦略の方向性
- Variety base
    - 1つのことをどの競合よりも徹底的にうまく多くの顧客に提供
        - 早い
        - 安い
        - わかりやすい
        - ect
- Need base
    - 特定セグメントの顧客とって`One stop shop`を目指す
        - XをしたければYを使っとけ
        - とりあえずXがあれば事足りる
- Access base
    - 特定のセグメントで自社でしか取り扱えない情報や財を確保する
        - Xがないと成り立たない
        - Y以外に選択肢がない

### ステークホルダーとのコミュニケーション

上層部とのコミュニケーション
- 上層部が知りたいこと
	- ステータス
		- 今の状況
	- ロードマップ
		- 方向性
	- ストラテジー
		- リソース配分
- 意識すること
	- 全ては会社のビジョン・ミッションにつながっていることを示す
	- データで語る
		- 売上や利益率などのビジネスメトリック
		- ユーザー成長率やエンゲージメント率などの顧客インパクト
		- ⚠️ 数字なしで語るのは、PMとして未熟に見える
	- 「リソースが足りない」は、以下2点を考えてからストーリーにして伝える
		- 会社がもっと人をアサインする合理性
		- 他の優先度項目との整合性

マーケティングチームとのコミュニケーション
- マーケティング活動のROIが至上命題であることを理解する
- プロダクトチームからの適切な情報開示が必要
	- コピーライティング、メッセージ作り、コンテンツ作り、ストーリーテリング
	- ==生の状態で情報を伝える（加工しない）==
- 営業チームが適切に売りに行けるかは、プロダクトマネジメントとプロダクトマーケティングの連携にかかっている

営業チームとのコミュニケーション
- PMは「営業職」の要素を持っている
	- PMも営業の一環として顧客の前に立ち、しかるべき情報を顧客に伝える場面が多々ある
- PMから、営業チームへ展開する情報
	- ロードマップ
	- プロダクト戦略
	- プロダクトに関するFAQ
	- プロダクトのデモ
	- 他の営業チームのWin事例やケーススタディのシェア


### 「業界を破壊する」について注意点
長年業界にいる「中の人」からすると、新しい解決策の有効性が判断できない可能性がある。
根本的に変わることへの強い抵抗がある。
しかし、どこかが着手して成功すると一気に広がる可能性がある。

Cutting edge よりも Bleeding Edge
Bleeding Edge
- **問題に対する切り込み方が鋭いイノベーション**
	- リセグメンテーション（市場の再定義）を行う方が、尖ったプロダクトになれる
