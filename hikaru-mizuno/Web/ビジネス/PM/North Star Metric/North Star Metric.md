# KPIの定義

### KPI is / isn't

| is                             | isn't                         |
| ------------------------------ | ----------------------------- |
| 数字                             | 言葉<br>（最高品質、即日配送、地域No1、etc）   |
| 比較可能<br>（前年比、地域別、プロダクト別）       | 単独の値<br>（100, 5000個, 3000人）   |
| 時系列データ<br>（過去3ヶ月、直近18ヶ月）       | ランダムデータ<br>（非連続データ）           |
| 自社で取得可能<br>（ソースが自社データ）         | 外部ソース依存<br>（マーケティングリサーチ、メディア） |
| 社内で共通理解があり、行動可能<br>（何のためのデータか） | 自己満足で終わっている<br>（大きい数字で見栄えを良く） |

# North Star Metric

### メリット  
- 判断軸をチーム内で共有できる
- 施策のインパクトや進捗を組織内に伝えやすい
- 説明責任をもてる

### 良いNSMの要素  
- ユーザーの体験とプロダクトの提供する価値がリンクしている
- ユーザーがプロダクトにどのくらい定着しているかを示す
- 長期的には”Up and to the right”に進む
- 収益に結びつくための”Leading Indicator”である（Not Gameableである）
    - Gameableとは、恣意的な数字あそび
- 組織内で理解してもらいやすい

### 実例
- Uber
    - 月間アクティブプラットフォーム利用者
- Amazon
    - プライムユーザーの購買点数
- Facebook
    - 直近10日間で7人以上友達を追加したユーザー数
- Airbnb
    - 予約された宿泊数
- Medium
    - 総読書時間

### 悪いNSMの要素  
- ダウンロード数
- 登録ユーザー数（DAU, MAU）
- MRR（Monthly Recurring Revenue）
    - Revenueとは、サービスの販売によって得たお金の「総額」を指す言葉

### （悪いNSMの要素は）なぜダメなのか？  
- Lagging Indicator（結果指標）をメトリックにしてしまっている
    - プロダクトが提供できる価値を高める、増やすことが目指すべきことなのに、結果良ければ何でもよしになってしまう
- 誰にでも分かる指標を安易に選んでしまう
    - 分かりやすいことがいつも正しいとは限らない


**Leading Indicatorを改善しなければ、Lagging Indicator は改善しない**
![](LL%20Indicator.png)


**NSMのLeading Indicatorを「広がり」「深さ」「頻度」「効率」の４軸で分ける**
![](Leading%20Indicator%20MECE.png)


### ⭐️NSMの注意点
- ==PMFが確立され、Growthの方向性が定まってからNSMを設定する==
    - 0 -> 1 ではなく、1 -> 100 のタイミング
- ==絶対数で設定する==
    - %（相対数）は増減率の場合に設定する
- 頻繁に変更しない
    - 1〜3年で達成する規模感
- 会社で１つ
- ==Trade off metrics==
    - NSMが上がっていればOK
    - 下がるKPIが出ることが必ずしも悪ではない
